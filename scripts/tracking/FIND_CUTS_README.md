# find_cuts — детектор «прыжков» камеры обсервера

Модуль ищет в VOD матча Apex моменты, когда наблюдательская камера
**телепортируется** между точками карты (смена POV игрока, переход на
killcam, прыжок на другой бой). Эти моменты ломают непрерывность пана/зума
и поэтому должны быть отрезаны до того, как мы начнём **сравнивать
положение кольца между соседними кадрами**.

На следующем шаге пайплайна мы детектируем смещение зоны (ring). Без
нарезки по катам алгоритм будет принимать резкий скачок камеры за
«сдвиг кольца» и портить результат. Поэтому `find_cuts` запускается
первым и отдаёт список интервалов, внутри которых камера движется
непрерывно — только на этих интервалах имеет смысл мерить ring drift.

## Как запустить

```powershell
powershell -ExecutionPolicy Bypass -File scripts\tracking\cuts.ps1 `
  -Video scripts\tracking\video.mp4
```

Выход складывается в `scripts/tracking/cuts_out/`:

- `cuts.json` — машинно-читаемый результат (см. ниже).
- `cuts.txt` — человекочитаемый отчёт с тремя секциями: `cuts`, `hud`, `gray`.
- `frame_cut_<N>_{before,at,after,after10}.jpg` — четыре кадра вокруг каждого
  ката, чтобы глазами проверить, что это действительно скачок.
- `overlay_cut_<N>.png` — наложение «до/после» для быстрой визуальной проверки.
- `run.log` — полный лог запуска.

## Как он работает

1. **Coarse-проход.** Идём по кадрам с шагом `coarse=300` (~5 секунд при 60fps).
   Для каждой пары соседних опорных кадров считаем:
   - `pixel_diff` — среднее абсолютное отличие после downscale (быстрый признак,
     что картинка вообще менялась);
   - `H` — гомография через SIFT + RANSAC, из неё `pan` и число инлайеров.
2. **Pinpoint.** Где `pixel_diff` или провал инлайеров подозрительный, спускаемся
   с шагом `fine=10` и ищем точный кадр перелома.
3. **Классификация события** (главная логика, см. `pinpoint_cut`):

   | Условие | Класс | Куда попадает |
   |---|---|---|
   | `Δpan ≥ 100px` и `pixel_diff ≥ 10` | `cut` | `events` — настоящая телепортация |
   | Регистрация упала, но `pixel_diff ≥ 15` | `cut` (fallback) | `events` — доверяем диффу |
   | `Δpan < 100px` и `pixel_diff ≥ 10` | `hud` | `hud_events` — zoom/killcam/overlay, камера на месте |
   | `pixel_diff` в зоне 5–10 | `gray` | `gray_zone` — ручной просмотр |
   | `pixel_diff < 5` | — | отбрасываем как шум регистрации |

   Идея: настоящий кат всегда переносит центр кадра в мировых координатах
   далеко (>100px после нормализации). Если картинка дёрнулась, а центр
   остался — это HUD-событие (включился zoom, всплыл killcam, обновился
   замкнувшийся ring overlay), и для ring drift это **не** проблема.

## Формат `cuts.json`

```json
{
  "video": "video.mp4",
  "fps": 59.94,
  "total_frames": 72168,
  "params": { "coarse": 300, "fine": 10, "threshold": 90, ... },
  "events":     [ { "frame": 13443, "t": 224.27, "delta": 254.0, "pixel_diff": 27.49, "classify": "cut" } ],
  "hud_events": [ { "frame": 13513, "t": 225.44, "delta":  53.4, "pixel_diff": 25.88, "classify": "hud" } ],
  "gray_zone":  [ { "frame": 36455, "t": 608.19, "delta": null,  "pixel_diff":  7.54, "classify": "gray" } ]
}
```

`events` — список «честных» катов, между которыми камеру можно считать
непрерывной. Следующий шаг пайплайна (ring drift) будет читать именно эти
интервалы.

## Параметры, которые имеет смысл крутить

- `--coarse` — крупный шаг (по умолчанию 300). Меньше = точнее, но дольше.
- `--fine` — мелкий шаг при pinpoint (10).
- `--threshold` — порог `pixel_diff` для подозрения (90 на coarse, 10 на pinpoint).
- `--min-delta-px` — минимальный сдвиг центра, при котором событие классифицируется
  как настоящий кат (по умолчанию 100). Если в твоём VOD много медленных пролётов
  камеры, увеличь — иначе будут ложные срабатывания.
- `--detector sift|orb` — SIFT точнее, ORB быстрее. По умолчанию SIFT + CLAHE.

## Зачем это нужно для ring drift

Алгоритм детекции смещения кольца сравнивает координаты круга в соседних
кадрах. Если между двумя кадрами случился кат, мы увидим «скачок кольца на
пол-карты» — но это будет артефакт камеры, а не реальный сдвиг зоны.

`find_cuts` режет VOD на безопасные сегменты:

```text
VOD: [───── seg A ─────][CUT][──────── seg B ────────][CUT][── seg C ──]
ring drift считаем  ⬆ только внутри одного сегмента
```

Внутри сегмента наблюдатель плавно панорамирует/зумит — H между кадрами
корректна, и мы можем честно мерить, на сколько пикселей (а после калибровки
канонической карты — на сколько мировых метров) сместился центр ring между
двумя моментами времени.

Канонические карты (`canonical_maps/*.json` + `*.png`) понадобятся как раз
на этом следующем шаге: чтобы перевести «сдвиг кольца в пикселях кадра» в
«сдвиг в мировых координатах конкретной карты Apex».
