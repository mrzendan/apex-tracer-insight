## Цель

Поднять покрытие трекинга команд: к существующему HSV-проходу добавить два независимых метода и собрать таблицу уверенности по совпадению их координат.

## Архитектура

Три независимых детектора прогоняются на одном и том же окне кадров (`--window/--step`). Каждый возвращает список траекторий с тегом источника. Дубликаты не схлопываются — складываются в общий `moving[]` с полем `source`. Согласие методов используется только для построения таблицы уверенности в отчёте.

### M1 — `hsv_strict` (текущий пайплайн)

Без изменений: `build_mask` по `hsv_presets.json`, `find_blobs` с дефолтными `min-area=15 / solidity=0.55`, линковка с `--link-dist`, отсев статики по `--static-thresh`. Все траектории помечаются `source="hsv_strict"`.

### M2 — `motion_diff` (frame-difference, основной fallback)

Идея: ищем то, что физически двигается на minimap, и только потом проверяем цвет.

1. Для каждой выборки кадра внутри ROI зоны minimap считаем `cv2.absdiff(prev_gray, cur_gray)` и бинаризуем (`--diff-thresh`, по умолчанию 12).
2. Накапливаем diff-маску морфологией (OPEN+CLOSE 3×3) и ищем контуры с `min-area=5`.
3. Для каждого blob'а берём медианный HSV-цвет пикселей под ним (на текущем кадре) и матчим к каждой команде через манхэттенское расстояние до центра её H-диапазона (с переносом для red-wrap). Порог `--color-tol` (по умолчанию 12 по H, S/V игнор).
4. Привязываем blob к команде с минимальной дистанцией; если ни одна не проходит порог — blob отбрасывается.
5. Линкуем через ту же `link_blobs`, помечаем `source="motion_diff"`.

Плюс: ловит тёмные/мелкие плашки, которые не дают сплошной HSV-маски, но имеют контрастный сдвиг кадр-к-кадру.

### M3 — `hsv_loose` (расширенный HSV, второй fallback)

Запускается всегда, не только при пустом M1.

- H-диапазон расширен на ±5, S/V min снижены до `max(20, original-30)`.
- `min-area=5`, `min-solidity=0.40`, `--static-thresh` локально снижен до 1 px.
- Та же линковка, `source="hsv_loose"`.

### Таблица уверенности

После сбора траекторий со всех методов для каждой команды:

1. Из каждого метода берём «лучшую» траекторию: с максимальным `path_px`. Получаем до 3 представителей: `p1, p2, p3` (медиана центроидов по точкам).
2. Считаем попарные расстояния и проверяем гейтом `--agree-radius` (по умолчанию `1.5 * link_dist`).
3. Метка `agree`:
   - `3/3` если все три попарно ≤ радиуса → confidence **HIGH**
   - `2/3` (любая пара) → **MEDIUM**, в отчёте указываем какие методы (`hsv_strict+motion_diff` и т.п.)
   - `1/3` (только один метод что-то нашёл) → **LOW**
   - `0/3` → **MISS**
4. Координата «итоговая» — среднее центроидов согласившихся методов.

## Изменения в файлах

### `scripts/tracking/motion_detect.py`

- Рефакторинг основного цикла: одна общая выборка кадров, но для каждого кадра помимо HSV-маски строится grayscale и сохраняется `prev_gray` для diff.
- Новые функции: `detect_motion_diff(prev_gray, cur_gray, frame_bgr, teams, params)`, `detect_hsv_loose(hsv_img, teams, params)`.
- `per_team_zone` становится `per_team_zone_method: dict[(slot, zone, method)] -> list[(frame_idx, [blob])]`.
- `link_blobs` вызывается по каждому ключу — траектории получают `source`.
- В `results[slot]`: `moving` теперь содержит элементы вида `{"source": "hsv_strict"|"motion_diff"|"hsv_loose", "points": [...], "displacement_px", "path_px", ...}`.
- Новая секция отчёта `confidence`: для каждой команды — `m1/m2/m3` (count траекторий), `agree` (3/3, 2/3, 1/3, 0/3), `consensus_xy` если есть.
- Новые CLI-флаги: `--diff-thresh 12`, `--color-tol 12`, `--loose-h 5`, `--loose-sv-drop 30`, `--agree-radius 60`.
- Overlay: каждая `source` рисуется своим стилем (strict — сплошная линия, diff — пунктир, loose — точки), чтобы было видно совпадения визуально.

### `scripts/tracking/motion_out/report.txt`

### `scripts/tracking/motion.ps1`

Добавить флаги-пробросы: `-DiffThresh`, `-ColorTol`, `-AgreeRadius` (с дефолтами). Остальное без изменений.

### `scripts/tracking/motion_out/motion_tracks.json`

К каждой записи в `moving` добавляется `source`. Добавлен блок `confidence_table` с разбивкой по командам.

## Что НЕ делаем сейчас

- Не трогаем детект смертей — будет отдельным скриптом.
- Не подключаем leaderboard-зоны как источник координат (можно добавить позже отдельным методом M4).
- Не меняем HSV-пресеты и `/admin/hsv`.

## Как проверять

После имплементации:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/tracking/motion.ps1 -Video scripts\tracking\game.mp4
```

Смотрим `motion_out/report.txt`: должно стать ≥15 команд с conf MED+, а слоты 5/9/10/11/14/16 — хотя бы LOW. Если останутся MISS, дальше смотрим overlay (по стилю линии видно, какой метод что нашёл).
