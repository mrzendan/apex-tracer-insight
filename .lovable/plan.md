## Что готово
Все 20 тегов команд распознаны корректно (vocab + snap + voting работают). Остаются 3 локальные проблемы и можно возвращаться к трекингу.

## Проблема 1 — `team_20 pts` всё ещё пустое

Из `report.txt`:
```
team_20  pts   52% ok / 28% parsed   examples: (пусто)
```
То есть OCR что-то читает (52% непустых кадров), но после валидации `0..100` всё отбрасывается → ни одного стабильного значения. У остальных команд тот же zone-шаблон работает (team_15=5, team_3=3, team_17=13).

Текущая зона `team_20.pts`:
- `x=1860 y=1011 w=52 h=50` — почти впритык к правому краю кадра (1920px) и шире, чем у других (50×50). Логотип `team_20` помечен `STATIC? 1 unique hashes` — намёк, что весь блок 20 рендерится «иначе» (правый край HUD). Скорее всего цифра «11» либо обрезана, либо в зону залезает соседний пиксель/иконка → OCR-кандидаты типа `H`, `II`, пустота.

**Шаги:**
1. В `hud_read.py` для `pts` сделать дамп **сырых** OCR-кандидатов (`pts_raw.json` по аналогии с `team_tags_raw.json`): по слотам — top-5 строк, что вернул tesseract, и что отбросил валидатор. Это покажет, режется цифра или читается мусор.
2. После дампа — либо сдвинуть/расширить зону `team_20.pts` (правую границу до 1920, h↑ до 56), либо ослабить препроцессинг (другой `psm`, инверсия, scale x2) **только для этого слота**.
3. Если OCR действительно видит «11», но валидатор отсекает — снять верхнюю границу 100 (сейчас pts может уходить в 100+ при долгих матчах? в Apex max обычно <60, но оставим 0..199 на всякий случай).

## Проблема 2 — `camera roi` не должна OCR-иться

В `report.txt` строки 11+ — OCR гонится по всему `minimap.camera roi` (1050×1030 px) и выдаёт длинные «стихи» вроде «ROC Esports… Team Liquid… NinjasinPyjamas». Это:
- замедляет проход (tesseract на огромной картинке),
- засоряет отчёт.

Зона нужна только как геометрия для других модулей (ring_locator/track_teams), сам текст внутри не нужен.

**Решение:** в `hud_read.py` добавить set `OCR_SKIP_ZONES = {("minimap", "camera roi")}` (или поле `"ocr": false` в самой зоне `zones.vod.json`). Для пропущенных зон не запускать OCR, в `report.txt` показывать `SKIP`.

## Проблема 3 — ошибка PowerShell после `git push`

Логи показывают:
```
remote: Resolving deltas: 100% ... main -> main
-Mode : Имя "-Mode" не распознано как имя командлета...
строка:4 знак:1
+ -Mode 'forward'
```

`push.ps1` отработал успешно (`git push` прошёл). Ошибка приходит **после** скрипта и означает, что PowerShell получил лишнюю строку `-Mode 'forward'` как отдельную команду. Причина — обратный апостроф (` ` `) в конце **последней** строки команды:
```
... `-Mode 'forward'      ← здесь стоит лишний ` после 'forward'
```
PS считает её продолжением и потом «выплёвывает» `-Mode 'forward'` отдельно.

**Решение:** ничего в коде не правим, просто корректная команда:
```powershell
powershell -ExecutionPolicy Bypass -File scripts\tracking\modules\hud_read\push.ps1 `
  -Video scripts\tracking\game_sp.mp4 `
  -TessCmd "C:\Program Files\Tesseract-OCR\tesseract.exe" `
  -Mode forward
```
(без backtick после `-Mode forward`, кавычки вокруг `forward` не обязательны). Добавлю короткую заметку об этом в `scripts/tracking/modules/hud_read/README.md`.

## Следующий шаг — возврат к трекингу команд

Когда фиксы выше уедут и `slot-to-tag.json` гарантированно правильный, у нас есть надёжный мост `slot → team tag` и точные `eliminations` (`t_first_dead`) для всех 20 команд. Это разблокирует доводку `track_teams`.

Из ранее зафиксированных в этой ветке проблем трекинга на Storm Point (`m-test-g1`):

- `THUG` стартует в углу карты (вне игровой зоны) → проблема инициализации первых кадров (`init_warmup_frames`/перенос якоря после прыжка с корабля).
- `FREE/ELITE/STAL` определяются вверху-слева, должны быть внизу-справа → перепутанные слот↔цветовой профиль (ID-switch на старте).
- `OBVN` стал тиммейтом `820/SRC` → ID-switch (близкие/похожие цвета).
- `S2` вообще не видно на карте → потерян слот после wipe-фолбэка.

**План работы по трекингу (отдельная волна, после фиксов выше):**

1. **GT-якоря.** Расширить `track_teams/assets/gt_anchors.json` (сейчас 5 точек) до ~30 ручных меток (слот × t) с разбросом по матчу. Это включает `eval_id_switches.py` для объективной метрики.
2. **Прогон матрицы** (`run_matrix.ps1`) уже есть — пересобрать на текущих данных, посмотреть `eval_id_switches.json` по 6 пресетам (`baseline / color_first / detect_first / hybrid / motion_first / strict_shape`) и выбрать базу.
3. **Init warmup.** Для первых N секунд (до приземления) увеличить порог принятия якоря и не плодить треки в углах карты — даст fix для `THUG`.
4. **Slot overrides.** Для проблемных цветов (`OBVN` vs `SRC`, `820/S2`, `ELITE/FREE/STAL`) — индивидуальные HSV-пресеты в `configs/hsv_presets.storm-point.json` или per-slot вес признака (color/motion/shape).
5. **UI карты** уже использует `SLOT_COLORS` из `team-colors.ts` (готово), проверим что цвета карточек на `/games/m-test-g1` соответствуют HUD.
