# Tracking Lab

Локальный пайплайн обработки VOD + страница визуализации в админке.

## Поток работы

1. Запускаешь `scripts/tracking/track_teams.py` на mp4 — получаешь `tracks.json`.
2. Открываешь `/admin/tracking-lab`.
3. Перетаскиваешь `tracks.json` (и опционально само видео `*.mp4`).
4. Смотришь треки команд на канонической карте + viewport обсервера, скрабишь по таймлайну.
5. При необходимости экспортируешь CSV.

## Формат `tracks.json`

См. `scripts/tracking/schema/tracks.schema.json`.

Кратко:

- `meta` — общие данные (видео, fps, размер канонической карты, мировые границы, список команд).
- `frames[]` — по одной записи на обработанный кадр:
  - `t` — секунды от начала обработки.
  - `frame` — индекс кадра в исходном видео.
  - `camera.zoom` — оценка масштаба (1.0 — без зума, >1 — зум-ин).
  - `camera.pan_canonical` — где центр кадра обсервера находится на канонической карте.
  - `camera.rotation_deg` — поворот.
  - `camera.registration` — `ok` / `low_confidence` / `failed`.
  - `tracks[]` — позиции команд:
    - `world` — мировые координаты (стабильные).
    - `canonical_px` — где плашка на канонической карте (для отрисовки).
    - `frame_px` — где плашка в кадре (для синхронной отрисовки на видео).
    - `angle_world_deg` — направление стрелки в мире.
    - `state` — `alive` / `low_conf` / `lost`.

## Почему так

- Считаем гомографию каждого кадра на канонической карте, поэтому зум/пан обсервера
  не ломает координаты — это базовый трюк sports analytics (футбол, баскетбол).
- Трекер Калмана работает в МИРОВЫХ координатах, не в пиксельных, — треки переживают
  смену зума и кратковременную потерю детекции.
- Все цвета команд берутся из тех же HSV-пресетов, что в `/admin/hsv`.
